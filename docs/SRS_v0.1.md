# 소프트웨어 요구사항 명세서 (SRS) v0.1

## 1. 문서 개요

|항목|내용|
|---|---|
|시스템|교내 분실물 관리 서비스|
|버전|0.1|
|작성 기준|`고객 요구사항.md`의 인터뷰, 개발 범위, 공통 제약 및 고객 요구사항 요약|
|범위|분실물 조회, 물품 정보 등록·관리, 보관·인도 상태 구분, 담당 부서 문의 방법 안내|
|제약|가상 데이터 사용. 실제 개인정보 및 학교 인증 연동 제외.|
|표기 원칙|원문에 확정되지 않은 세부 조건은 임의로 확정하지 않고 ‘미정’으로 표시한다.|

## 2. 기능 요구사항

|ID|기능 요구사항|근거|우선순위|비고·수용 기준|
|---|---|---|---|---|
|FR_00|학생은 등록된 분실물 정보를 목록 또는 검색 결과로 조회할 수 있어야 한다.|NEEDS_1, SC1|필수|조회 대상 데이터가 결과에 표시되어야 한다.|
|FR_01|학생은 분실물의 보관 여부와 공개 가능한 보관 위치를 확인할 수 있어야 한다.|NEEDS_1, SC1|필수|보관 상태와 공개 위치가 물품별로 확인되어야 한다. 공개 항목·위치의 상세 수준은 정책 결정이 필요하다.|
|FR_02|학생은 정해진 조건을 사용해 분실물 정보를 검색할 수 있어야 한다.|NEEDS_1, SC1|필수|검색 조건과 검색 결과 정렬 기준은 미정이며 정책으로 확정한다.|
|FR_03|권한이 있는 행정 담당자는 분실물 센터로 접수된 습득 물품을 관리하기 위해 물품 정보를 등록할 수 있어야 한다.|NEEDS_2, SC2, ADD_02|필수|필수 입력값이 누락되면 저장을 막고 누락 항목을 안내해야 한다. 입력 항목은 미정이다.|
|FR_04|권한이 있는 행정 담당자는 등록된 분실물 정보를 조회하고 수정할 수 있어야 한다.|NEEDS_2, SC2, ADD_02|필수|수정 가능한 항목과 변경 이력 보존 여부는 미정이다.|
|FR_05|권한이 있는 행정 담당자는 물품을 ‘보관 중’ 또는 ‘인도 완료’ 상태로 기록하고 변경할 수 있어야 한다.|NEEDS_3, SC3|필수|변경된 상태가 학생 조회와 담당자 관리 화면에 일관되게 반영되어야 한다. 처리·정정 권한은 미정이다.|
|FR_06|학생은 보관 담당 부서와 해당 부서에 문의하는 방법을 확인할 수 있어야 한다.|NEEDS_4, SC6|필수|부서명과 승인된 문의 방법을 표시한다. 구체적인 연락 수단과 문구는 미정이다.|
|FR_07|조회 화면과 조회 결과에는 개인 휴대전화 번호를 표시하지 않아야 한다.|NEEDS_6, SC8, C_1|필수|학생에게 제공되는 화면·응답 데이터에 개인 휴대전화 번호가 없어야 한다.|
|FR_08|행정 담당자의 물품 등록·수정·상태 변경 기능은 권한이 있는 담당자에게만 허용되어야 한다.|NEEDS_2, NEEDS_3, ADD_02|필수|행정 기능에 대한 비인가 쓰기 작업은 거부되어야 한다. 담당자 식별 및 인증 방법은 미정이며 학교 인증 연동은 제외한다.|
|FR_09|습득 학생은 학생용 앱을 통해 자신이 습득한 물품 정보를 직접 등록할 수 있어야 한다.|NEEDS_2, SC2, ADD_01|필수|학생용 등록 경로에서 물품 정보를 제출할 수 있어야 한다. 필수 입력 항목, 중복 처리, 등록 정보가 학생 조회 결과에 공개되는 시점은 미정이다.|

## 3. 비기능 요구사항 및 품질 요구사항

|ID|품질 특성|요구사항|측정·수용 기준|상태·근거|
|---|---|---|---|---|
|NFR_00|정보보호·개인정보 보호|조회 목적에 필요한 정보만 수집·표시하고 개인 휴대전화 번호를 공개하지 않아야 한다.|저장 항목과 학생용 화면·응답을 점검해 불필요한 개인정보 및 개인 휴대전화 번호가 노출되지 않는지 확인한다.|개인 번호 비공개 및 실제 개인정보 제외 확정. 세부 공개 항목 미정. S4, C_1|
|NFR_01|접근 통제|행정 담당자용 등록·수정·상태 변경 기능은 권한이 있는 행정 담당자만 수행할 수 있어야 한다. 학생은 학생용 앱의 습득 물품 등록 기능을 사용할 수 있어야 한다.|비인가자의 행정 기능 쓰기 요청은 거부되어야 하며, 학생용 등록 경로와 행정 기능의 권한 경계를 점검한다.|담당자·학생 식별 방식과 등록 남용 방지 기준 미정. NEEDS_2, NEEDS_3, ADD_01, ADD_02|
|NFR_02|정확성·무결성|물품 상태와 등록 정보는 화면 및 조회 결과에서 일관되게 제공되어야 한다.|상태 변경 후 담당자 화면과 학생 조회 결과의 상태가 일치해야 한다.|상태 구분 요구 확정. 정정·이력 정책 미정. NEEDS_3|
|NFR_03|사용성|학생은 방문 전에 보관 여부·위치·문의 방법을 쉽게 찾을 수 있어야 한다.|대표 학생이 조회 과업을 수행하는 사용성 점검을 실시하고, 과업 성공률·소요 시간 목표를 정해 충족 여부를 평가한다.|측정 방법·목표값 미정. S1, NEEDS_1, NEEDS_4|
|NFR_04|사용성·운영 효율성|행정 담당자는 적은 부담으로 물품을 등록하고 상태를 관리할 수 있어야 한다.|등록 소요 시간과 반복 문의량의 기준선을 측정하고 개선 목표 및 측정 기간을 정해 비교한다.|기준선·목표값 미정. S2, NEEDS_7|
|NFR_05|성능 효율성|분실물 조회와 물품 등록 결과는 업무 흐름을 방해하지 않는 시간 안에 제공되어야 한다.|예상 이용량을 정한 뒤 조회·저장 응답 시간의 목표값과 측정 조건을 합의하고, 해당 부하에서 측정해 평가한다.|목표 시간·예상 이용량 미정. 서비스 목표에서 도출|
|NFR_06|가용성·복구성|서비스 운영 중 장애나 데이터 오류가 발생하면 정해진 절차로 서비스를 복구할 수 있어야 한다.|운영 시간, 백업 주기, 복구 시간·데이터 손실 허용 목표를 정하고 복구 절차를 점검한다.|운영 책임자 및 정량 목표 미정.|
|NFR_07|운영성·유지보수성|서비스 운영 책임자와 물품 관리 절차가 정해져 있어야 하며, 운영에 필요한 변경과 오류 대응이 가능해야 한다.|운영 담당자, 문의·장애 대응 절차, 데이터 정정 절차를 문서화하고 담당자가 이를 확인할 수 있어야 한다.|운영 책임자 미정.|
|NFR_08|테스트 데이터 안전성|개발·실습 환경은 가상 데이터를 사용하고 실제 개인정보 및 학교 인증 연동을 포함하지 않아야 한다.|환경 설정, 연동 구성, 샘플 데이터를 점검해 실제 개인정보와 학교 인증 연동이 없음을 확인한다.|확정. C_1|
