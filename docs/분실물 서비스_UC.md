|관련 고객 요구·정책 ID|NEEDS_1, NEEDS_4, NEEDS_6, SC1, SC6, SC8, FR_00~FR_02, FR_06~FR_07, Pol_02, Pol_05, Pol_09|

|시작 사건|분실 학생이 잃어버린 물건의 보관 여부를 확인하려고 서비스의 조회 화면을 연다.|
|기본 흐름|1. 서비스가 검색 화면을 제공한다.<br>2. 분실 학생이 정해진 검색 조건을 입력하거나 목록을 요청한다. `[논의: 검색 조건·필수 입력 여부]`<br>3. 서비스가 조건에 맞는 물품을 검색한다.<br>4. 서비스가 일치하는 물품 목록을 보여준다.<br>5. 분실 학생이 확인할 물품을 선택한다.<br>6. 서비스가 해당 물품의 공개 가능한 정보, 보관 여부·위치, 담당 부서와 문의 방법을 보여준다.<br>7. 개인 휴대전화 번호 등 공개 금지 정보는 결과에 포함하지 않는다.|
|대안·예외 흐름|A1 — 검색 결과 없음: **분기 지점:** 3단계 검색 후 → **조건:** 일치하는 물품이 없음 → **대응:** 서비스가 결과가 없음을 안내하고 검색 조건을 바꿀 수 있게 한다 → **복귀/종료:** 2단계로 복귀하거나 조회를 종료한다.<br><br>A2 — 조건 누락·형식 오류: **분기 지점:** 2단계 입력 후 → **조건:** 필수 조건이 누락되었거나 입력 형식이 유효하지 않음 `[논의: 필수 조건·형식]` → **대응:** 서비스가 수정할 항목을 안내한다 → **복귀/종료:** 2단계로 복귀한다.<br><br>A3 — 공개 위치·문의 정보 미등록: **분기 지점:** 6단계 표시 시 → **조건:** 공개 가능한 위치 또는 문의 안내가 등록되지 않음 → **대응:** 서비스는 확인되지 않은 정보를 임의로 만들지 않고 등록된 정보만 표시한다 `[논의: 정보가 없을 때 사용자 안내 문구]` → **복귀/종료:** 나머지 조회 정보를 보여준 뒤 종료한다.<br><br>A4 — 비공개 정보 요청: **분기 지점:** 6단계 정보 제공 시 → **조건:** 개인 휴대전화 번호 등 공개 금지 정보가 데이터에 있음 → **대응:** 서비스가 해당 정보를 숨긴다 → **복귀/종료:** 허용된 정보만 표시하고 7단계로 진행한다.|
|사후조건|**성공:** 조회 결과가 표시된다. 조회만으로 물품 데이터는 변경되지 않는다.<br>**실패·취소:** 조회를 종료해도 데이터는 변경되지 않는다. 입력한 검색 조건의 임시 보존 여부는 `[논의]`다.|
|미확정 사항·고객 질문|검색 조건과 정렬 기준은 무엇인가? 공개할 물품 설명 및 위치의 상세 수준은 어디까지인가? 담당 부서명·공식 문의 방법·정보 미등록 시 안내 문구는 무엇인가? (고객 문서 Q_07~Q_08, 정책 Pol_05·Pol_09)|

## UC_02 — 습득 물품 앱 등록

|항목|설명|
|---|---|
|ID / 이름|UC_02 / 습득 물품 앱 등록|
|주 액터|습득 학생|
|사용자와 목표|습득 학생이 자신이 주운 물품을 학생용 앱으로 바로 등록하여 분실자가 해당 물품을 찾을 수 있게 한다.|
|관련 고객 요구·정책 ID|NEEDS_2, SC2, ADD_01, FR_09, NFR_01, Pol_01, Pol_06, Pol_07|
|사전조건|습득 학생이 학생용 앱의 등록 기능을 사용할 수 있다. 앱이 등록 요청을 처리할 수 있다. 학교 인증 연동은 범위에서 제외되어 있으므로 로그인이나 실명 확인을 사전조건으로 가정하지 않는다.|
|시작 사건|습득 학생이 주운 물품을 앱에 등록하려고 등록 기능을 연다.|
|기본 흐름|1. 앱이 습득 물품 등록 화면을 제공한다.<br>2. 습득 학생이 물품 정보를 입력한다. `[논의: 필수·선택 항목, 사진 첨부 허용 여부]`<br>3. 습득 학생이 등록을 제출한다.<br>4. 앱이 입력값의 필수 항목과 형식을 확인한다. `[논의: 항목·형식 규칙]`<br>5. 앱이 등록 정보를 저장하고 등록 완료를 안내한다.<br>6. 앱은 저장 결과를 확인할 수 있게 한다. 등록 정보가 분실 학생의 검색 결과에 공개되는 시점은 별도 정책 결정 전까지 확정하지 않는다.|
|대안·예외 흐름|A1 — 필수 정보 누락·형식 오류: **분기 지점:** 4단계 검증 → **조건:** 필수값 누락 또는 형식 오류 → **대응:** 앱이 오류 항목을 안내하고 잘못된 입력을 저장하지 않는다 → **복귀/종료:** 2단계로 복귀한다.<br><br>A2 — 중복 의심: **분기 지점:** 4단계 검증 → **조건:** 기존 등록 정보와 같은 물품일 가능성이 있음 → **대응:** 중복 판정 기준과 안내 방법이 미정이므로 자동 병합·거절을 확정하지 않는다 `[논의]` → **복귀/종료:** 중복 처리 정책 확정 후 흐름을 보완한다.<br><br>A3 — 저장 실패: **분기 지점:** 5단계 저장 → **조건:** 저장 오류 또는 연결 중단 → **대응:** 앱이 등록되지 않았음을 안내하고 재시도하도록 한다. 입력값 보존 여부는 `[논의]`다 → **복귀/종료:** 입력이 보존되면 3단계로 복귀하고, 보존되지 않으면 입력부터 다시 진행하거나 종료한다.<br><br>A4 — 등록 취소: **분기 지점:** 2~3단계 사이 → **조건:** 습득 학생이 취소 → **대응:** 제출 전 입력 데이터를 등록하지 않는다. 임시저장 여부는 `[논의]`다 → **복귀/종료:** 등록 화면을 닫고 종료한다.|
|사후조건|**성공:** 습득 물품 정보가 시스템에 등록된다. 검색 결과 노출 여부·시점은 확정되지 않았다.<br>**실패:** 등록 레코드가 새로 생성되지 않는다. 재시도 가능한 입력값의 임시 보존 여부는 `[논의]`다.<br>**취소:** 제출 전이면 등록 레코드는 생성되지 않는다. 임시 입력값 삭제·보존 조건은 `[논의]`다.|
|미확정 사항·고객 질문|필수 등록 항목은 무엇인가? 등록 즉시 검색 결과에 공개되는가, 검토 후 공개되는가? 중복 물품은 어떻게 판별·처리하는가? 학생을 식별하거나 남용을 방지할 별도 기준이 필요한가? 사진 첨부가 허용되는가? (고객 문서 Q_01~Q_03, 정책 Pol_06·Pol_07)|

## UC_03 — 센터 접수 습득 물품 등록

|항목|설명|
|---|---|
|ID / 이름|UC_03 / 센터 접수 습득 물품 등록|
|주 액터|행정 담당자|
|사용자와 목표|행정 담당자가 분실물 센터에 접수된 습득 물품을 등록하여 분실물 정보를 관리하고 학생 조회에 활용할 수 있게 한다.|

|시작 사건|행정 담당자가 센터에 접수된 물품을 시스템에 등록하기로 한다.|

|대안·예외 흐름|A1 — 필수값 누락·형식 오류: **분기 지점:** 5단계 검증 → **조건:** 필수값이 없거나 형식이 유효하지 않음 → **대응:** 시스템이 수정할 항목을 안내하고 저장하지 않는다 → **복귀/종료:** 3단계로 복귀한다.<br><br>A2 — 중복 가능성: **분기 지점:** 5단계 검증 → **조건:** 학생 앱 등록 또는 기존 센터 등록과 중복될 가능성이 있음 → **대응:** 중복 처리 규칙은 `[논의]`; 확정 전에는 자동 병합·삭제를 전제하지 않는다 → **복귀/종료:** 확인 결과에 따라 3단계로 복귀하거나 등록을 종료한다.<br><br>A3 — 저장 실패: **분기 지점:** 6단계 저장 → **조건:** 저장 오류 또는 연결 중단 → **대응:** 시스템이 실패를 안내하고 재시도를 허용한다. 입력값 보존 여부는 `[논의]`다 → **복귀/종료:** 보존된 경우 4단계로 복귀하고, 아니면 3단계부터 다시 진행하거나 종료한다.<br><br>A4 — 권한 없음: **분기 지점:** 1단계 진입 또는 6단계 저장 → **조건:** 행정 담당자에게 해당 기능 권한이 없음 → **대응:** 시스템이 등록을 거부하고 권한 오류를 안내한다 → **복귀/종료:** 데이터 변경 없이 종료한다.<br><br>A5 — 등록 취소: **분기 지점:** 3~4단계 사이 → **조건:** 행정 담당자가 제출 전에 취소 → **대응:** 새 등록은 생성하지 않는다. 임시저장 및 입력값 보존은 `[논의]`다 → **복귀/종료:** 등록 화면을 닫고 종료한다.|
|사후조건|**성공:** 센터 접수 물품 레코드가 생성되어 행정 담당자가 관리할 수 있다.<br>**실패:** 새 레코드가 생성되지 않으며 기존 레코드는 변경되지 않는다. 재시도를 위한 입력값 보존 여부는 `[논의]`다.<br>**취소:** 제출 전에 취소하면 새 레코드는 생성되지 않는다. 임시 입력값 보존·삭제 조건은 `[논의]`다.|
|미확정 사항·고객 질문|행정 등록의 필수 항목과 초기 상태는 무엇인가? 학생 앱 등록과 중복 시 누가 판단하고 어떤 레코드를 유지하는가? 행정 담당자 권한의 부여·회수와 인증 방법은 무엇인가? (고객 문서 Q_03~Q_04, 정책 Pol_06·Pol_07)|

|기본 흐름|1. 행정 담당자가 물품 관리 기능을 연다.<br>2. 시스템이 관리 가능한 물품 목록을 보여준다.<br>3. 행정 담당자가 대상 물품을 찾고 선택한다.<br>4. 시스템이 현재 물품 정보와 상태를 보여준다.<br>5. 행정 담당자가 수정할 정보 또는 새 상태를 입력한다. 상태 값은 최소 ‘보관 중’, ‘인도 완료’다.<br>6. 행정 담당자가 변경을 저장한다.<br>7. 시스템이 권한과 입력값을 확인한다.<br>8. 시스템이 변경 사항을 저장하고 결과를 안내한다.<br>9. 학생 조회에도 공개되는 정보라면 승인된 공개 항목과 현재 상태를 반영한다. 공개 시점 및 정보 범위는 정책에 따른다.|
|대안·예외 흐름|A1 — 대상 물품 없음: **분기 지점:** 2~3단계 검색 → **조건:** 원하는 레코드가 없음 → **대응:** 시스템이 결과 없음을 알린다 → **복귀/종료:** 다른 조건으로 2단계에 복귀하거나 종료한다.<br><br>A2 — 수정 권한 없음: **분기 지점:** 6~7단계 저장 → **조건:** 행정 담당자에게 해당 작업 권한이 없음 → **대응:** 시스템이 변경을 거부하고 권한 오류를 알린다 → **복귀/종료:** 기존 데이터 유지 후 종료한다.<br><br>A3 — 잘못된 입력: **분기 지점:** 7단계 검증 → **조건:** 필수값 누락 또는 허용되지 않는 상태값 → **대응:** 시스템이 오류를 표시하고 저장하지 않는다 → **복귀/종료:** 5단계로 복귀한다.<br><br>A4 — 상태 정정 요청: **분기 지점:** 5단계 상태 변경 → **조건:** 기존 상태를 잘못 기록했거나 인도 완료를 되돌려야 함 → **대응:** 정정 권한·승인·이력 규칙이 미정이므로 `[논의]`; 규칙에 따라 정정 또는 거부한다 → **복귀/종료:** 허용되면 6단계로 복귀, 거부되면 기존 상태를 유지하고 종료한다.<br><br>A5 — 동시 수정: **분기 지점:** 7단계 저장 직전 → **조건:** 다른 담당자가 먼저 같은 레코드를 변경함 → **대응:** 충돌 감지·최신 데이터 표시 여부는 `[논의]` → **복귀/종료:** 정책에 따라 최신 내용을 확인하고 4단계부터 다시 처리하거나 종료한다.<br><br>A6 — 저장 실패 또는 취소: **분기 지점:** 6~8단계 → **조건:** 행정 담당자가 저장 전 취소하거나 저장 오류 발생 → **대응:** 취소 시 미저장 변경을 적용하지 않는다. 저장 오류 시 실패를 안내한다. 미완료 변경의 임시 보존은 `[논의]` → **복귀/종료:** 재시도 시 5단계로 복귀, 취소 시 기존 레코드를 유지하고 종료한다.|
|사후조건|**성공:** 요청된 정보 또는 상태 변경이 저장되고, 학생 공개 정보는 적용되는 공개 정책에 따른다. 변경 이력 보존은 `[논의]`다.<br>**실패:** 변경이 저장되지 않고 기존 레코드가 유지된다. 실패한 변경 내용을 임시 보존하는지는 `[논의]`다.<br>**취소:** 저장 전에 취소하면 기존 레코드는 변경되지 않는다. 미저장 입력의 보존 여부는 `[논의]`다.|

## UC_05 — 습득물 접수 안내 (후보)

|항목|설명|
|---|---|
|ID / 이름|UC_05 / 습득물 접수 안내|
|주 액터|습득 학생|
|사용자와 목표|습득 학생이 주운 물건을 학교에 맡길 장소와 방법을 확인하여 올바른 접수처에 전달한다.|
|관련 고객 요구·정책 ID|NEEDS_5, SC4, Pol_10. 서비스 포함 여부 미정.|
|사전조건|이 유스케이스가 서비스 범위에 포함되어야 한다. 접수 장소와 방법에 관해 승인된 안내가 제공되어야 한다. 두 조건 모두 `[논의]`다.|
|시작 사건|습득 학생이 물건을 어디에 맡길지 몰라 서비스에서 접수 안내를 찾는다.|
|기본 흐름|1. 습득 학생이 접수 안내를 연다.<br>2. 서비스가 승인된 접수 장소와 방법을 보여준다.<br>3. 습득 학생이 안내를 확인하고 서비스 이용을 종료한다. `[논의: 안내 기능 자체의 범위 승인 필요]`|
|대안·예외 흐름|A1 — 안내 기능이 범위에 포함되지 않음: **분기 지점:** 서비스 범위 결정 → **조건:** 고객이 기능을 제외하거나 기존 안내만으로 충분하다고 결정 → **대응:** 앱에서 이 유스케이스를 제공하지 않는다 → **복귀/종료:** 시스템 유스케이스가 되지 않으며, 필요하면 기존 학교 안내로 유도할지 별도 결정한다 `[논의]`.<br><br>A2 — 접수 정보 미등록·변경: **분기 지점:** 2단계 안내 표시 → **조건:** 승인된 최신 접수 장소·방법이 등록되지 않았거나 운영 정보가 변경됨 → **대응:** 잘못된 장소를 안내하지 않고 안내 정보가 없음을 알리거나 공식 안내 채널을 표시한다. 대체 안내 방식은 `[논의]` → **복귀/종료:** 유효한 정보가 있으면 2단계로 복귀하고, 없으면 종료한다.|
|사후조건|**성공:** 습득 학생이 승인된 접수 안내를 확인한다. 물품 등록이나 접수 처리가 자동으로 발생하지 않는다.<br>**실패·취소:** 접수 안내 데이터는 변경되지 않는다. 기능이 범위에서 제외되면 서비스 내 유스케이스를 제공하지 않는다.|
|미확정 사항·고객 질문|기존 학교 접수 안내가 있는가? 앱에서 안내할 필요가 있는가? 장소·운영 시간·접수 방법·담당 부서를 누가 관리하고 최신 상태로 유지하는가? (고객 문서 Q_09, 정책 Pol_10)|
