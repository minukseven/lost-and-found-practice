# 요구사항 추적표 (RTM) v0.1

## 1. 목적과 표기

고객 요구사항 문서의 고객 요구(NEEDS), 범위(SC), 공통 제약(C_1)이 SRS의 기능 요구사항(FR), 비기능 요구사항(NFR), 정책(Pol)에 반영되었는지 추적한다. 추적표 ID는 `RTM_01`부터 부여했다. 비기능 추적에서는 ‘정확성’, ‘사용성’처럼 목표가 특정되지 않은 일반 품질 속성은 제외하고, 측정 가능한 목표를 제안할 수 있는 항목만 다룬다.

## 4. 정량 목표가 필요한 비기능 요구사항

아래 값은 초기 서비스의 일반적인 제안 목표다. 고객 문서에 확정된 값은 아니므로 운영 책임자와 예상 이용량을 확인해 승인한 뒤 SRS의 목표값으로 확정한다. 시험 환경, 측정 구간, 네트워크 조건을 동일하게 기록한다.

|추적 ID|고객 근거|SRS 연결 ID|정량 목표 제안|측정 방법·수용 기준|
|---|---|---|---|---|
|RTM_17|NEEDS_1, S1: 방문 전 보관 여부·위치 조회|NFR_05|동시 사용자 50명 기준, 조회 응답 시간은 95백분위수 2초 이내로 한다.|검색 요청을 반복 측정하고 응답 시간 분포를 계산한다. 시험 데이터 규모와 환경을 함께 기록한다.|
|RTM_18|NEEDS_2, NEEDS_7, S2: 등록 시간 부담 감소|NFR_04|일반 물품 1건 등록 완료 시간은 담당자 기준 평균 1분 이내를 목표로 한다.|필수 입력 항목 확정 후 담당자 5명 이상이 각 5건 이상 등록하도록 하고 중앙값 및 90백분위수를 기록한다. 우선 제안 목표는 중앙값 1분 이내다.|
|RTM_19|서비스 목표: 학생이 방문 전에 정보를 확인|NFR_06|조회 서비스 가용성 월 99.5% 이상을 제안한다.|월간 전체 시간에서 사전 공지된 정기 점검 시간을 제외한 서비스 제공 가능 시간을 측정한다. 운영 시간과 점검 제외 기준은 승인 필요하다.|

## 6. 일반 품질 속성의 처리

|SRS 요구 ID|항목|RTM 처리|이유|
|---|---|---|---|
|NFR_02|정확성·무결성|별도 비기능 추적 대상에서 제외. FR_05의 상태 반영 기준과 Pol_03, Pol_08에서 기능·정책으로 추적.|일반 품질 속성으로만 제시하지 않고 고객이 요구한 상태 구분 기능과 처리 정책에 연결했다.|
|NFR_03|사용성|별도 비기능 추적 대상에서 제외.|정량 목표와 측정 기준이 합의되지 않았다. 사용성 과업 목표를 정할 경우 후속 RTM/SRS 개정에 추가한다.|
|NFR_06|가용성·복구성|일반 문구는 추적 대상에서 제외. 월간 가용성에 대해 RTM_19 목표를 제안.|복구 시간·백업 기준은 고객 요구에 수치 근거가 없어 목표를 제안하지 않았다. 운영 요구가 확정되면 수치화한다.|
|NFR_07|운영성·유지보수성|추적 대상에서 제외.|운영 문서 작성은 일반 품질 목표이며 고객 요구에 정량 근거가 없다. 운영 책임자 지정은 Pol_12로 추적한다.|
